# GRPO 200-Step Drive-Backed Run Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run resumable 200-step GRPO training from the full SFT model, saving checkpoints and fair 50-episode evaluations at steps 50, 100, 150, and 200 under a new Google Drive artifact root.

**Architecture:** A dedicated GRPO run orchestrator owns Drive-root validation, four bounded Trainer invocations, resume selection, and boundary evaluations. `src/train/grpo.py` remains responsible only for constructing and running one configurable Trainer segment; artifact helpers validate and write a GRPO-specific manifest after all required checkpoints and metric files exist.

**Tech Stack:** Python, TRL `GRPOTrainer`, Transformers Trainer checkpoints, BrowserGym/MiniWoB, Google Drive, pytest.

---

```python
def build_grpo_job_config(
    init_model_path: str,
    output_dir: str,
    *,
    max_steps: int = 50,
    save_steps: int = 10,
    resume_from_checkpoint: str | None = None,
    **overrides: Any,
) -> dict[str, Any]:
    config = {...existing defaults..., "max_steps": max_steps, "save_steps": save_steps}
    if resume_from_checkpoint is not None:
        config["resume_from_checkpoint"] = resume_from_checkpoint
    config.update(overrides)
    return config

def run_grpo_training(config: dict[str, Any]) -> Any:
    ensure_grpo_artifact_dirs(config)
    trainer = build_grpo_trainer(config)
    try:
        resume = config.get("resume_from_checkpoint")
        if resume is not None and not Path(resume).is_dir():
            raise ValueError(f"GRPO resume checkpoint does not exist: {resume}")
        stats = trainer.train(resume_from_checkpoint=resume)
        trainer.save_model(config["output_dir"])
        return stats
    finally:
        del trainer
        gc.collect()
        if torch.cuda.is_available():
            torch.cuda.empty_cache()
```

Keep model/prompt/reward behavior unchanged. Do not compile `flash-attn`; Colab keeps native PyTorch SDPA if no matching wheel is specified.

- [ ] **Step 3: Implement tool-call policy**

Add `NOOP` to action schema. Native BrowserGym `step("NOOP")` returns current
observation, reward `0.0`, `done=False`, and does not issue a browser action.
Add tests for parsing and one native-environment no-op step.

`GRPOToolPolicy` loads a checkpoint tokenizer/model and renders the same
tool-enabled Qwen prompt contract used by GRPO. It parses a representative
Qwen `<tool_call>` completion for function `click` and parameter `target`, then
returns native BrowserGym action text `click('target')`. Invalid/missing tool
calls return supported `NOOP` rather than an arbitrary action. Unit tests cover
valid tool call, malformed completion, and unsupported function. Do not route this
output through `normalize_action_text`, which is action-text-only.

```text

```

Validate total steps are positive and divisible by checkpoint interval, require
the SFT model directory to load via `AutoConfig` and `AutoTokenizer`, use
`prepare_drive_artifact_root`, and reject roots outside Drive. For every
boundary `50,100,150,200`:

1. call `run_grpo_training` with absolute max step boundary and latest resume
   checkpoint;
2. verify `checkpoint-<boundary>` exists;
3. release trainer/model GPU memory before evaluation;
4. call `run_grpo_eval_phase` with that boundary;
5. retain checkpoint and metric immediately on Drive.

After step 200, verify final export and call `write_grpo_run_manifest`. A
boundary is complete only when its checkpoint has all resumable files and its
metric JSON parses to all three numeric metric fields; use an atomic JSON writer
for metric output. Rerun logic skips only complete boundaries. It retrains and
reevaluates checkpoint-without-metric, metric-without-checkpoint, and
partial/invalid-metric boundaries; explicit resume from a valid checkpoint with
missing evaluation resumes training/evaluation from that boundary safely. Add
tests for each recovery combination. For a
50-step smoke gate, invoke same runner with `--total-steps 50` and
`--checkpoint-every 50`; its dynamic manifest contains only boundary 50.
Interrupted reruns accept `--resume-from-checkpoint`; derive completed
boundaries from existing metric files, skip them, and continue only unfinished
boundaries. Do not rerun/overwrite a completed boundary.

`apply_artifact_root` uses the returned `grpo_output_dir` instead of composing
it independently.
